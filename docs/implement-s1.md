# S1 实施计划：准备、解析与符号计算

先实现 `prepare` 所需的问题准备，以及 LaTeX 解析、符号计算和结果转换。
输入直接使用已有 Python 模型，worker 通信通过 JSON codec。
当前已实现请求校验及显式化简的纵向切片，其他运算待实现；模型与状态语义遵循
[接口契约](interfaces.md)，类型位置见[模型组织说明](schemas.md)。

## 当前已交付的切片

- `prepare` 在独立 worker 内清理定界符、解析标量算术表达式并返回 ready 快照。
- `compute` 重查快照与原始输入的一致性，再化简并转换公开结果；篡改快照返回错误。
- `run` 在同一 worker 内准备和化简，只解析一次。
- 精确小数、分数、变量、整数幂和分式已验证；分母排除点保留为条件，并进入
  顶层答案 LaTeX，复制结果不会遗漏条件。
- 方程、函数、非整数幂、内嵌微积分、符号假设和数值方法尚未启用。
- IPC 使用严格 JSON，包含版本、类型、容量、深度、重复键与非有限数值检查。
- spawn worker 的超时、取消、崩溃、坏 JSON、超大消息及后续请求恢复已有测试。

下文列出整个 S1 的任务与验收标准。CLI、OCR、媒体、后台任务和展示层暂不保留
空接口；先实现数学核心，再按实际使用需求定义外围接口。

## 1. 目标与顺序

核心链路：

```text
ComputeRequest
  → 基础检查
  → 格式清理与 LaTeX 解析
  → 运算、变量和原式约束检查
  → PreparationResponse：ready + PreparedProblem，或补充项/失败诊断
  → 对已确认问题执行符号计算
  → 结果分类与数学内容转换
  → ComputeResponse
```

按以下顺序逐步交付，每一步补对应测试：

1. 请求基础检查、缺失参数和失败响应。
2. 公式清理、解析适配、预览和准备成功响应。
3. 求值与化简，跑通第一条核心链路。
4. 求导、不定/定积分、单变量方程求解，逐项开放能力。
5. 串联 `run`，接入执行保护后开放公共计算入口。

本阶段不实现 OCR、自动运算推断、数值求解、计算步骤、后台任务或界面。
已有长期模型继续保留，未完成的功能不能出现在已启用能力中。

## 2. 模块职责

| 位置 | 本阶段工作 | 输出边界 |
|---|---|---|
| application.py | 公开入口，轻量预检后提交任务 | 只暴露公开模型 |
| preflight.py | 父进程与 worker 共用的模型、容量和能力检查 | 不依赖应用、执行器或数学后端 |
| pipeline.py | worker 分发、准备和化简流程 | 不导入 application 或 execution |
| schemas/operations.py | 各运算及嵌套参数的 validate() | 返回 ValidationIssue，不构造响应、不抛输入异常 |
| parsing/normalize.py | 移除配对公式定界符、清理外部空白、记录修改 | 清理后文本与修改记录 |
| parsing/latex.py | 调用解析库，适配数学结构，提取符号和原式约束 | 仅内部使用的解析结果 |
| solving/symbolic.py | 按显式运算调用符号算法，判断是否完成 | 内部数学结果及分类依据 |
| solving/serialization.py | 数学对象转 MathValue、条件与 LaTeX | 无第三方对象的公开数学内容 |
| test/test_parsing.py | 清理与解析语义测试 | 保真、失败和能力边界 |
| test/test_solving.py | 数学结果和分类测试 | 数学语义与条件 |
| test/test_pipeline.py | 准备、计算和 run 的核心流程测试 | 状态、交互项和最终响应 |

先实现这些模块的内部核心函数。应用层公共入口继续遵循 execution 的隔离、
总时限和取消约定，不额外创建无超时的公开计算接口。单元测试可直接验证
内部核心；公共入口的执行保护单独接入，不要求先实现整套通用 codec。

## 3. prepare：从用户意图得到明确问题

公开签名保持不变：

```python
prepare(request, *, options=None, control=None) -> PreparationResponse
```

### 基础检查

直接构造的 dataclass 也需要检查，不能因暂未实现 JSON 输入就省略校验：

Spec 自身规则由 validate() 执行，构造时允许不完整或无效参数。prepare
委托 ComputeRequest 组合各模型的 validate() 并转换问题，不按具体运算编写
重复的参数校验分支。执行选项先自校验，再作为独立容量策略的输入。类型/取值无效
映射为 error，缺失或冲突映射为 needs_input；混合问题返回 error 并保留补充项。

- schema_version 为已知整数版本，bool 不视为整数。
- 输入模型、运算模型、嵌套字段和集合类型正确，字符串和容量满足限制。
- LaTeX 非空，原始输入保留；本阶段图片返回 unsupported。
- operation 为空时返回 needs_input + missing_operation，请用户显式选择。
- 求导阶数、精度为范围内正整数，符号声明和求解未知量不得重复。
- 求导目标、积分变量、求解未知量或极限参数缺失时返回具体补充项；
  其中尚未启用的运算直接返回 unsupported，不生成假 ready 问题。
- 积分上下限须成对提供；上下限都空表示不定积分。
- 声明矛盾、原式与显式参数冲突时不静默改写。

能力逐步开放：先仅接受默认方法 symbolic_first 或 symbolic_only；前者在
本阶段只尝试符号方法。numeric_only、显式数值搜索参数、未启用定义域和
尚未支持的符号假设返回 unsupported。普通符号声明可保留，假设是否启用
由能力与兼容测试决定，不把 real 求解域当成所有符号的实数假设。

请求步骤时保留偏好，后续计算返回 steps=unavailable 和步骤诊断；不影响
已完成答案。附加近似尚未启用时保留精确结果并返回明确提示，不伪造近似。

### 清理、解析与语义检查

基础参数充分后，清理并解析公式，生成预览，再检查数学结构：

- 只去除明确的格式包装，不补括号、等号或猜测变量名。
- 区分表达式、方程和公式中已经包含的运算符；检查与请求是否一致。
- 公式中有导数或积分时，识别运算对象与参数，只应用一次运算。
- 原式包含的信息与显式参数相同则合并；冲突则返回 needs_input。
- 目标变量未出现在表达式中不自动判错，例如常量对 x 求导可以为 0。
- 矩阵、多变量方程组等尚未启用结构返回 unsupported，即使解析库能够读取。
- 无法保留原式约束的输入应明确拒绝，不把简化后的公式视为原式的全部含义。

### 准备响应

| 情况 | status | 必要内容 |
|---|---|---|
| 请求明确且结构受支持 | ready | problem、preview，无待确认项 |
| 缺参数或冲突 | needs_input | 至少一个 InputRequest，problem 为空 |
| 已知但未支持的能力 | unsupported | 具体诊断，problem 为空 |
| 类型、版本或公式无效 | error | 对应阶段诊断，problem 为空 |

PreparedProblem 保存原始输入、确定后的运算对象 LaTeX、具体运算、符号声明、
偏好和清理记录。求导/积分的外层运算符及参数已经进入 operation；求解仍
保留方程，不能将解析库返回的解误当待求解公式。快照不携带 SymPy 对象。

## 4. 解析适配：先保证原式含义

在 parsing 内定义内部解析上下文，集中保存原文、规范化文本、第三方表达式、
符号映射、已识别运算和原式约束。该上下文不进入 schemas，不跨进程传递。
不要让 solving 或 application 各自再次直接调用解析库。

固定依赖组合的兼容测试先覆盖：整数、精确小数、变量、下标变量、分数、幂、
括号、函数、方程、一阶导数和积分上下限。支持范围由语义测试决定。

必须验证的行为：

- 有限小数按十进制原文构造精确值，不能先转机器 float 再恢复分数。
- 对数的底数与约定一致；未经确认的写法返回 unsupported，不悄悄改变含义。
- 解析器提前求导、积分、化简或解方程时，适配层能保留原式及操作语义；
  做不到时拒绝相关写法，不能重复执行或直接接受预先生成的答案。
- 分母排除点、根式和对数约束不能在解析或化简时无声丢失。
- 语法无效、语法暂不支持和数学结构不支持分别诊断，不统一当作无解。

单次 run 在内部复用解析上下文；独立 compute 可重新解析快照，且须检查
快照与原始输入的一致性，不能信任调用方手工构造的“已确认”对象。

## 5. 符号计算与结果转换

先完成求值和化简，再按顺序补其他运算。每项先有语义测试，再在能力接口中
标记支持；使用现有 OperationSpec，不新增入口专用参数。

| 运算 | 核心策略 | 关键约束 |
|---|---|---|
| 求值 | 精确代入和求值 | 代入值单独解析，避免浮点精度损失 |
| 化简 | simplify | 保留原式条件，不注入未经声明的假设 |
| 求导 | diff | 目标顺序和阶数明确，外层导数不重复应用 |
| 积分 | integrate | 区分不定、定积分，处理积分常数与收敛性 |
| 单变量求解 | solveset | 先开放实数解集，保留分母排除点和条件 |

极限和其他能力后续扩展，不因为枚举存在就立即实现。方程解析必须保留原式，
不能把第三方解析器提前得到的答案当作 solveset 的输入。

计算侧生成 MathValue、完整答案 LaTeX、条件、性质和完整性：

- 表达式使用 ExpressionValue；有限解使用 FiniteSetValue。
- 确认无解使用空有限集及 complete，执行失败使用 value=null。
- 全集、无限集和条件集使用 SymbolicSetValue，分别判断完整性。
- 未完成积分、导数等保留内容，返回 unsupported + symbolic_not_completed，
  并区分 mixed 与 unevaluated。
- 发散必须有判定依据；NaN、zoo 或算法异常不等于已证明发散。
- 不定积分的积分常数由计算侧加入展示及结果，不能只由展示侧追加。
- 原式条件放入 MathCondition；成功响应附实际使用的 PreparedProblem。
- 所有嵌套字段不含第三方对象，公开数值使用文本，不用 default=str 掩盖泄漏。

这里的数学内容转换必须与计算一起实现；通用 JSON 编解码仍可后置。

## 6. 测试与完成标准

| 分组 | 最低用例 |
|---|---|
| 基础检查 | 空公式、错误类型/版本、未知运算、缺变量、非法阶数、未支持输入 |
| 准备流程 | ready 快照、needs_input 可操作项、原文保留、变量/上下限冲突 |
| 解析保真 | 定界符、下标变量、精确小数、对数语义、运算符只应用一次 |
| 求值/化简 | `1/3+1/6` 得到 1/2，代入求值，带原式约束的化简 |
| 求导 | x^3 二阶导数为 6x，常量对 x 求导为 0 |
| 积分 | x 的不定积分、x 在 [0,1] 的积分为 1/2、未求出结果 |
| 收敛性 | 1/x 在 [0,1] 发散，在 [-1,1] 的普通积分不能返回主值 0 |
| 求解 | x^2-2=0 的完整根，实数域 x^2+1=0 空集，x=x 全集，分母排除点 |
| 结果模型 | 性质/完整性正确，条件未丢，步骤不可用不影响答案，无数学对象泄漏 |
| 编排 | run 未就绪即返回准备响应；已就绪走计算且复用上下文 |

比较数学语义，必要时核对稳定的 LaTeX 展示。先跑相关测试，公共模型或流程
变更再跑全量测试；当前已有契约测试继续保留。

执行隔离、总时限、取消、资源回收和 JSON codec 已有测试。后续完成标准是：
每项新增运算通过相应数学验收用例，再经现有 prepare/compute/run 公开链路验证，
保持结果契约和执行保护。CLI、后台任务和图片功能按实际开发进度另行实现。
